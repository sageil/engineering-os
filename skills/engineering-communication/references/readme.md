# README Guide

A README should help a capable reader understand the project and reach a first successful result quickly.

Preferred order:

1. What the project does
2. Why someone would use it
3. Quick start
4. Installation
5. Common usage
6. Configuration
7. Examples
8. Troubleshooting
9. Contributing
10. Architecture, only when useful
11. Reference

Rules:

- Put the first successful command or interaction near the top.
- Show the expected result after setup.
- State prerequisites before commands that depend on them.
- Keep architecture after usage unless architecture is the product.
- Do not repeat package metadata already visible elsewhere unless it helps the reader decide or act.
- Prefer tested commands and current filenames.
